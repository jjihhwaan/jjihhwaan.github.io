## 블로그를 만든 이유

Knights Frontier 3기 첫 미션으로 GitHub Pages 블로그를 만들었다.
Chirpy Starter를 사용했고, 앞으로 공부한 내용과 문제 풀이를 정리할 예정이다.

## 기본 구성

`jjihhwaan.github.io` 저장소를 만들고 GitHub Actions로 배포했다.
한국어와 시간대를 설정하고, 미션에서 지정한 카테고리 6개를 추가했다.

- 개발
- CTF/Wargame
- Bug Bounty
- 블로그/기술문서
- 논문/컨퍼런스
- 공모전/자격증

처음에는 화면이 너무 비어 보여서 그로밋 프로필 사진을 넣었다.
다크 모드를 적용하고 소개 문구의 기울임을 없앴다.
배경색과 메뉴 강조 색상도 조금씩 바꿨다.

## 만들면서 막혔던 부분

### 글을 저장했는데 카테고리가 안 보였다

카테고리별 글을 만들었는데 일부만 표시됐다.
파일 위치를 확인해보니 `_posts` 안에서 다시 `_posts/파일명`을 입력해서
폴더가 중복으로 만들어져 있었다.

파일을 모두 `_posts` 바로 아래로 옮긴 뒤 카테고리 6개가 표시됐다.
파일을 만들 때 현재 어느 폴더에 있는지 확인해야 했다.

### 수정한 폰트가 다시 원래대로 보였다

소개 문구의 폰트를 바꿨는데 메뉴를 이동하면 이전 모습으로 보이기도 했다.
페이지마다 같은 스타일 파일을 사용하고 있어서 캐시를 원인으로 의심했다.

`_config.yml`에서 PWA의 오프라인 캐시를 끄고 다시 확인한 뒤에는
폰트가 돌아가는 현상이 보이지 않았다.

### 배포가 성공해도 색상이 바뀌지 않았다

색상을 바꾸는 코드를 추가했지만 화면은 그대로였다.
확인해보니 다크 모드에 적용할 CSS 선택자가 잘못되어 있었다.

현재 테마에 맞게 아래처럼 수정했다.

```scss
:root[data-bs-theme="dark"] {
  /* 다크 모드 색상 설정 */
}
```

배포가 성공했다고 해서 원하는 디자인까지 제대로 적용된 것은 아니었다.
실제 화면에서도 확인해야 했다.

### 설명 한 줄을 바꿨다가 배포가 실패했다

블로그 설명을 수정하면서 아래처럼 입력했다.

```yaml
description: >- 보안·개발 공부와 문제 풀이 기록
```

`>-`를 사용할 때는 내용을 다음 줄에 들여써야 하는데 같은 줄에 적었다.
한 줄짜리 설명이라 아래처럼 고쳤고, 다시 배포에 성공했다.

```yaml
description: "보안·개발 공부와 문제 풀이 기록"
```

이 설명은 화면 왼쪽에 보이는 소개 문구와도 별개였다.
왼쪽 소개 문구는 `tagline`에서 수정한다.

## 마무리

블로그를 만드는 것보다 수정한 내용이 왜 안 보이는지 확인하는 데 시간이 더 걸렸다.
덕분에 파일 경로, 설정 문법, 배포 상태를 확인하는 방법을 조금 익혔다.

기본 구성은 끝났으니 이제 공부한 내용을 하나씩 올려보려고 한다.
